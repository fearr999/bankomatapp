# Corpi

Полноценная Field Service Management платформа (диспетчер + руководитель +
полевой сотрудник), строится по ТЗ. Старое пилотное Flutter-приложение
поверх Google Apps Script удалено из репозитория — вся разработка теперь
идёт здесь, включая мобильное приложение (см. ниже).

> Внутренние тестовые email вида `@fsm.local` — это только логины из seed-скрипта,
> к названию продукта отношения не имеют.

## Стек

- **API**: Node.js + TypeScript + Express + Prisma + PostgreSQL, JWT-авторизация с ролями.
- **Web**: Next.js (App Router) + TypeScript + Tailwind, тёмная/светлая тема, компоненты в духе shadcn/ui.
- **Mobile**: Next.js PWA (устанавливается на телефон, работает офлайн) поверх того же API — для полевых сотрудников.
- **Landing**: отдельное Next.js-приложение (`platform/landing`) — маркетинговая
  страница на thecorpi.com, ссылки "Войти"/"Создать компанию" ведут на
  app.thecorpi.com (сама панель — это `platform/web`). Деплоится отдельно от
  приложения, к API/базе не обращается.

## Мультитенантность (разделение по компаниям)

Каждая компания — отдельная `Organization`, единственная граница изоляции в
системе. Любая новая компания регистрируется сама (`/register` в веб-панели —
название компании + первый администратор), получает свою пустую БД внутри
общей схемы и не видит данные других компаний ни в списках, ни по прямому
id (проверено: попытка обратиться к чужой заявке/клиенту/позиции склада по
id возвращает 404, а не данные). Email пользователя уникален глобально —
это одновременно и логин, поэтому два разных сотрудника в разных компаниях
не могут использовать один email.

Существующие данные (в т.ч. уже развёрнутые на Railway) при накатывании
миграции не стираются — все старые записи автоматически попадают в
`Legacy Organization`, дальше работают как обычно.

Новая компания при регистрации (`/register`) получает **14 дней бесплатного
пробного периода**. После истечения, если организация не оплатила, доступ
ко всему API блокируется (`402 Payment Required`) — веб и мобильное
приложение показывают экран "свяжитесь с нами" со ссылкой на Telegram, за
5 дней до истечения — предупреждающий баннер сверху. Оплата пока не
автоматизирована (нет платёжного шлюза — Stripe не выводит средства в
Узбекистан, для B2B здесь обычнее счёт, чем самостоятельная оплата картой):
после того как компания оплатила счёт вручную, доступ включает сам владелец
платформы:
```bash
cd platform/api
npm run activate-org -- "название компании"      # включить доступ
npm run activate-org -- "название компании" --deactivate  # выключить обратно
```
Организации, созданные до этой функции (`trialEndsAt` не задан, в т.ч.
`Legacy Organization`), под ограничение не попадают.

Ссылка "Написать в Telegram" на экране блокировки и в баннере ведёт на
отдельного **support-бота** (`TELEGRAM_SUPPORT_BOT_TOKEN`, отдельный токен
от `TELEGRAM_BOT_TOKEN` уведомлений выше) — он сам отвечает клиенту
(`/start` — приветствие, любое сообщение — подтверждение получения) и, если
задан `TELEGRAM_SUPPORT_ADMIN_CHAT_ID`, пересылает входящие сообщения вам.
Username бота фронтенд узнаёт сам через публичный `GET /public/support-bot`
(getMe), обновлять ссылку в коде не нужно. Без токена кнопка ведёт на
запасную ссылку `t.me/thecorpi`. Подробности — в `.env.example`.

## Что уже работает

- Авторизация по email/паролю, роли `ADMIN / DISPATCHER / MANAGER / WORKER`.
- Модуль **Заявки**: полный жизненный цикл статусов из ТЗ (Новая → Назначена →
  В пути → Прибыл → В работе → Ожидает материалы / Требуется согласование →
  Завершена → Закрыта / Отменена), карточка заявки с историей изменений и
  комментариями, назначение исполнителя.
- Модуль **Dashboard**: активные/завершённые/в работе/новые/отменённые заявки,
  сотрудники онлайн/офлайн, просроченные по SLA, лента последних событий —
  всё в реальном времени из БД.
- Модуль **Диспетчерский центр**: карта (OpenStreetMap, без API-ключа) с
  сотрудниками и активными заявками, drag-n-drop назначение, опрос раз в 8с.
- Модуль **Сотрудники**: карточки, KPI (всего/завершено/в работе, рейтинг),
  контакты, последняя геопозиция, история заявок.
- Модуль **Бригады**: создание, состав, руководитель, добавление/удаление
  участников, текущая загрузка.
- Модуль **Фотоотчёты**: единая лента с датой/временем/координатами/исполнителем/объектом, загрузка со страницы заявки.
- Модуль **Чек-листы**: конструктор шаблонов (checkbox/текст/число, обязательность) + заполнение на заявке с историей.
- Модуль **Карта** (общая): сотрудники/объекты/активные заявки со слоями-переключателями.
- Модуль **Оборудование**: карточка, гарантия, ТО, история обслуживания через привязанные заявки.
- Модуль **Склад**: материалы/запчасти, приход/выдача/возврат/списание с пересчётом остатка.
- Модуль **CRM**: карточка клиента — контакты, объекты с оборудованием, заявки, договоры, история взаимодействий.
- Модуль **Аналитика**: SLA, среднее время выполнения, эффективность по сотрудникам/бригадам, график за 14 дней.
- Модуль **"Обслуживание банкоматов"**: банкоматы/картоматы (тип оборудования), заполненность кассет, инкассация, контроль открытия/закрытия, аварийный вызов (создаёт срочную заявку).
- **AI-модуль (архитектура)**: единая точка `POST /ai/analyze` под все направления анализа из ТЗ (фото, эффективность, прогноз загрузки/поломок, аномалии, рекомендации, умный поиск) — сейчас возвращает заглушку в том же контракте, в котором будет отвечать подключённая модель; результаты сохраняются в `AiInsight`.
- **Мобильное приложение** (`platform/mobile`): устанавливаемое PWA для полевого сотрудника — вход, список «моих» заявок, карточка заявки со сменой статуса и комментариями, заполнение чек-листа, фото со снятием координат, офлайн-очередь фото (IndexedDB, автоотправка при восстановлении сети), фоновый GPS check-in раз в 30с. Нижняя навигация на 4 вкладки (Заявки/Карта/Уведомления/Профиль) — Карта показывает маршрут до объекта текущей открытой заявки и кнопку построения маршрута во внешней навигации, Уведомления — историю из общего центра уведомлений с бейджем непрочитанных. Дизайн-токены (радиусы, высота кнопок) сверены с `Corpi_Full_Design_Guide`. Дополнительно обёрнуто в Capacitor — можно собрать нативный **.apk** для Android (см. «Сборка APK» ниже). В нативной сборке доступен вход по биометрии (Face ID / отпечаток, `@aparajita/capacitor-biometric-auth`) — включается в профиле, блокирует приложение при каждом открытии и после возврата из фона; в браузере/PWA просто не отображается, так как плагина там нет. Там же — нативный push через Firebase Cloud Messaging (`@capacitor/push-notifications`): в браузере/PWA работает Web Push, в нативной сборке автоматически переключается на FCM — один и тот же тумблер "Push-уведомления" в профиле.
- Модуль **Уведомления**: внутренний центр уведомлений (список, отметка прочитанным) + каналы **Telegram**, **Email**, **Web Push** и **FCM** (нативный push в мобильном приложении) — Telegram привязывается через deep-link (`/start <код>`), email дублируется автоматически на логин сотрудника без отдельной привязки. События (назначение заявки, аварийный вызов по банкомату) дублируются во все подключённые каналы. Требуют `TELEGRAM_BOT_TOKEN`, `SMTP_HOST`/`SMTP_PORT`/`SMTP_USER`/`SMTP_PASS` и/или `FIREBASE_SERVICE_ACCOUNT` в `.env`; без них соответствующий канал просто выключен, всё остальное работает как обычно.
- Каркас со всеми 15 модулями ТЗ в навигации; из них не реализован только раздел **Интеграции** (ждёт реальных ключей CRM/телефонии).

## Дорожная карта (что дальше)

1. **Интеграции** — Bitrix24, amoCRM, Odoo, ERPNext, карты, WhatsApp, телефония (нужны реальные ключи от вас).
2. Подключить реальную модель к `/ai/analyze` вместо заглушки, когда будет решено, каким провайдером пользоваться.
3. Уведомления сейчас — внутренний центр + Telegram + Email; SMS можно добавить туда же по той же схеме, когда появится провайдер (для Узбекистана — Eskiz.uz/Play Mobile, международные вроде Twilio регион часто не покрывают).
4. Мобильное приложение — уже обёрнуто в Capacitor, биометрия и нативный push через Firebase Cloud Messaging подключены (см. выше). Из нативного не сделано: iOS-сборка (нужен Mac/Apple Developer аккаунт).
5. Оплата подписки сейчас — счёт + ручная активация (см. выше). Когда появится
   подходящий провайдер платежей для Узбекистана — можно подключить
   самостоятельную оплату вместо ручной активации.

Каждый пункт — это отдельная миграция БД + API-модуль + страницы веба, по
той же схеме, что уже сделана для "Заявок".

## Запуск локально

### 1. База данных
Нужен PostgreSQL (локально или в облаке — Supabase/Neon/Railway подойдут для старта).

### 2. API
```bash
cd platform/api
cp .env.example .env      # впишите DATABASE_URL и придумайте JWT_SECRET
npm install
npm run prisma:migrate    # создаст таблицы
npm run seed               # тестовые пользователи (admin@fsm.local / password123 и т.д.)
npm run dev                 # http://localhost:4000
```

Чтобы включить уведомления в Telegram — впишите `TELEGRAM_BOT_TOKEN` (от
`@BotFather`) в этот же `.env` и перезапустите API. Без него сервер работает
как обычно, просто канал Telegram неактивен (виден в `/notifications`).

### 3. Веб-панель
```bash
cd platform/web
cp .env.local.example .env.local
npm install
npm run dev                 # http://localhost:3000
```

Войдите как `admin@fsm.local` / `password123`.

### 4. Мобильное приложение (полевой сотрудник)
```bash
cd platform/mobile
cp .env.local.example .env.local
npm install
npm run dev                 # http://localhost:3100
```
Войдите как `worker@fsm.local` / `password123` (или `worker2@fsm.local`).
Заявку нужно предварительно назначить сотруднику через веб-панель (Диспетчерский
центр или карточка заявки), иначе список «Мои заявки» будет пуст. На телефоне
можно установить как приложение через «Добавить на экран Домой» (PWA) —
или собрать полноценный `.apk` (см. ниже).

### 5. Сборка APK (Android)

Мобильное приложение — статическая сборка Next.js (`output: "export"`),
обёрнутая в [Capacitor](https://capacitorjs.com) (`platform/mobile/android`).
Собрать APK локально нельзя без Android SDK, поэтому сборка идёт через GitHub
Actions (у раннера есть выход в интернет к серверам Google):

1. Разверните `platform/api` на публичном хостинге, чтобы у него был
   постоянный `https://` адрес — телефон должен куда-то стучаться.
2. В репозитории: **Actions → Build mobile APK → Run workflow**, укажите
   этот адрес в поле `api_url`.
3. После сборки (~5 минут) APK лежит в артефактах запуска —
   `corepi-mobile-debug-apk`. Это debug-сборка (подписана debug-ключом
   Android) — устанавливается на любой телефон через «Разрешить установку
   из неизвестных источников», для Google Play нужен отдельный release-ключ.

Локально можно собрать статический экспорт и открыть его в браузере как
предпросмотр (без реальной установки на телефон):
```bash
cd platform/mobile
npm run build   # создаёт out/
npm run serve   # http://localhost:3100 — просто статика, без APK
```
