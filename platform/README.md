# FSM Platform — Milestone 1

Полноценная Field Service Management платформа (диспетчер + руководитель +
полевой сотрудник), строится по ТЗ. Живёт в этом репозитории рядом с
существующим Flutter-приложением (`/lib`, `/backend`) — то приложение
продолжает работать на банкоматах/мерче без изменений, пока платформа
разрабатывается отдельно.

## Стек

- **API**: Node.js + TypeScript + Express + Prisma + PostgreSQL, JWT-авторизация с ролями.
- **Web**: Next.js (App Router) + TypeScript + Tailwind, тёмная/светлая тема, компоненты в духе shadcn/ui.
- **Mobile**: пока остаётся текущее Flutter-приложение; на следующем этапе переключим его с Google Apps Script на этот API.

## Что уже работает (Milestone 1)

- Авторизация по email/паролю, роли `ADMIN / DISPATCHER / MANAGER / WORKER`.
- Модуль **Заявки**: полный жизненный цикл статусов из ТЗ (Новая → Назначена →
  В пути → Прибыл → В работе → Ожидает материалы / Требуется согласование →
  Завершена → Закрыта / Отменена), карточка заявки с историей изменений и
  комментариями, назначение исполнителя.
- Модуль **Dashboard**: активные/завершённые/в работе/новые/отменённые заявки,
  сотрудники онлайн/офлайн, просроченные по SLA, лента последних событий —
  всё в реальном времени из БД.
- Каркас со всеми 15 модулями ТЗ в навигации — остальные помечены "скоро" и
  показывают заготовку страницы, чтобы архитектура была видна целиком с
  первого дня.

## Что ещё не реализовано (дорожная карта)

В порядке вероятного приоритета — но зависит от того, что нужнее вам:

1. **Диспетчерский центр** — карта, drag-n-drop заявок между сотрудниками, live-трекинг (нужен источник геопозиции с мобильного).
2. **Сотрудники / Бригады** — карточки, KPI, состав, техника, календарь загрузки.
3. **Мобильное приложение** — перевести текущий Flutter-app с Google Apps Script на этот API (переиспользуем большую часть экранов), добавить построение маршрута, видео, подпись клиента, голосовые заметки.
4. **Фотоотчёты** — единая лента с EXIF/гео-данными, интеграция с Attachment.
5. **Чек-листы** — конструктор шаблонов (сейчас в БД есть только заготовка).
6. **Карта** (общая) — сотрудники/клиенты/объекты/банкоматы/маршруты/история.
7. **Оборудование** — карточка, история обслуживания, гарантия.
8. **Склад** — материалы, запчасти, выдача/возврат/списание.
9. **CRM** — карточка клиента, договоры, история взаимодействий.
10. **Аналитика** — отчёты по сотрудникам/бригадам/SLA/KPI/финансам.
11. **Уведомления** — push/email/Telegram/SMS + внутренний центр.
12. **Интеграции** — Bitrix24, amoCRM, Odoo, ERPNext, карты, WhatsApp, Telegram, телефония.
13. **"Обслуживание банкоматов"** — специализированный модуль: банкоматы/картоматы, инкассация, загрузка кассет, аварийные вызовы.
14. **AI-модуль** — анализ фото, прогноз поломок/загрузки, аномалии, умный поиск.

Каждый пункт — это отдельная миграция БД + API-модуль + страницы веба, по
той же схеме, что уже сделана для "Заявок".

## Запуск локально

### 1. База данных
Нужен PostgreSQL (локально или в облаке — Supabase/Neon/Railway подойдут для старта).

### 2. API
```bash
cd platform/api
cp .env.example .env      # впишите DATABASE_URL и придумайте JWT_SECRET
npm install
npm run prisma:migrate    # создаст таблицы
npm run seed               # тестовые пользователи (admin@fsm.local / password123 и т.д.)
npm run dev                 # http://localhost:4000
```

### 3. Веб-панель
```bash
cd platform/web
cp .env.local.example .env.local
npm install
npm run dev                 # http://localhost:3000
```

Войдите как `admin@fsm.local` / `password123`.
