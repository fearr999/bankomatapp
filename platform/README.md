# FSM Platform

Полноценная Field Service Management платформа (диспетчер + руководитель +
полевой сотрудник), строится по ТЗ. Старое пилотное Flutter-приложение
поверх Google Apps Script удалено из репозитория — вся разработка теперь
идёт здесь, включая будущее мобильное приложение (см. дорожную карту).

## Стек

- **API**: Node.js + TypeScript + Express + Prisma + PostgreSQL, JWT-авторизация с ролями.
- **Web**: Next.js (App Router) + TypeScript + Tailwind, тёмная/светлая тема, компоненты в духе shadcn/ui.
- **Mobile**: Next.js PWA (устанавливается на телефон, работает офлайн) поверх того же API — для полевых сотрудников.

## Что уже работает

- Авторизация по email/паролю, роли `ADMIN / DISPATCHER / MANAGER / WORKER`.
- Модуль **Заявки**: полный жизненный цикл статусов из ТЗ (Новая → Назначена →
  В пути → Прибыл → В работе → Ожидает материалы / Требуется согласование →
  Завершена → Закрыта / Отменена), карточка заявки с историей изменений и
  комментариями, назначение исполнителя.
- Модуль **Dashboard**: активные/завершённые/в работе/новые/отменённые заявки,
  сотрудники онлайн/офлайн, просроченные по SLA, лента последних событий —
  всё в реальном времени из БД.
- Модуль **Диспетчерский центр**: карта (OpenStreetMap, без API-ключа) с
  сотрудниками и активными заявками, drag-n-drop назначение, опрос раз в 8с.
- Модуль **Сотрудники**: карточки, KPI (всего/завершено/в работе, рейтинг),
  контакты, последняя геопозиция, история заявок.
- Модуль **Бригады**: создание, состав, руководитель, добавление/удаление
  участников, текущая загрузка.
- Модуль **Фотоотчёты**: единая лента с датой/временем/координатами/исполнителем/объектом, загрузка со страницы заявки.
- Модуль **Чек-листы**: конструктор шаблонов (checkbox/текст/число, обязательность) + заполнение на заявке с историей.
- Модуль **Карта** (общая): сотрудники/объекты/активные заявки со слоями-переключателями.
- Модуль **Оборудование**: карточка, гарантия, ТО, история обслуживания через привязанные заявки.
- Модуль **Склад**: материалы/запчасти, приход/выдача/возврат/списание с пересчётом остатка.
- Модуль **CRM**: карточка клиента — контакты, объекты с оборудованием, заявки, договоры, история взаимодействий.
- Модуль **Аналитика**: SLA, среднее время выполнения, эффективность по сотрудникам/бригадам, график за 14 дней.
- Модуль **"Обслуживание банкоматов"**: банкоматы/картоматы (тип оборудования), заполненность кассет, инкассация, контроль открытия/закрытия, аварийный вызов (создаёт срочную заявку).
- **AI-модуль (архитектура)**: единая точка `POST /ai/analyze` под все направления анализа из ТЗ (фото, эффективность, прогноз загрузки/поломок, аномалии, рекомендации, умный поиск) — сейчас возвращает заглушку в том же контракте, в котором будет отвечать подключённая модель; результаты сохраняются в `AiInsight`.
- **Мобильное приложение** (`platform/mobile`): устанавливаемое PWA для полевого сотрудника — вход, список «моих» заявок, карточка заявки со сменой статуса и комментариями, заполнение чек-листа, фото со снятием координат, офлайн-очередь фото (IndexedDB, автоотправка при восстановлении сети), фоновый GPS check-in раз в 30с.
- Каркас со всеми 15 модулями ТЗ в навигации.

## Дорожная карта (что дальше)

1. **Уведомления** — push/email/Telegram/SMS + внутренний центр (нужны реальные токены/провайдер от вас).
2. **Интеграции** — Bitrix24, amoCRM, Odoo, ERPNext, карты, WhatsApp, Telegram, телефония (нужны реальные ключи от вас).
3. Подключить реальную модель к `/ai/analyze` вместо заглушки, когда будет решено, каким провайдером пользоваться.
4. Мобильное приложение сейчас — PWA; при необходимости настоящих нативных возможностей (push-уведомления в фоне, биометрия) можно обернуть в Capacitor/Expo позже без переписывания логики.

Каждый пункт — это отдельная миграция БД + API-модуль + страницы веба, по
той же схеме, что уже сделана для "Заявок".

## Запуск локально

### 1. База данных
Нужен PostgreSQL (локально или в облаке — Supabase/Neon/Railway подойдут для старта).

### 2. API
```bash
cd platform/api
cp .env.example .env      # впишите DATABASE_URL и придумайте JWT_SECRET
npm install
npm run prisma:migrate    # создаст таблицы
npm run seed               # тестовые пользователи (admin@fsm.local / password123 и т.д.)
npm run dev                 # http://localhost:4000
```

### 3. Веб-панель
```bash
cd platform/web
cp .env.local.example .env.local
npm install
npm run dev                 # http://localhost:3000
```

Войдите как `admin@fsm.local` / `password123`.

### 4. Мобильное приложение (полевой сотрудник)
```bash
cd platform/mobile
cp .env.local.example .env.local
npm install
npm run dev                 # http://localhost:3100
```
Войдите как `worker@fsm.local` / `password123` (или `worker2@fsm.local`).
Заявку нужно предварительно назначить сотруднику через веб-панель (Диспетчерский
центр или карточка заявки), иначе список «Мои заявки» будет пуст. На телефоне
можно установить как приложение через «Добавить на экран Домой» (PWA).
